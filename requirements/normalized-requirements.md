## 2. 目标站点摘要

**禅道（ZenTao）** 是一款全生命周期应用生命周期管理（ALM）系统，主要功能模块包括：

- **我的地盘**：个人工作看板，聚合待办、任务、需求、Bug、日程
- **产品管理**：需求生命周期管理、计划与发布管理
- **项目/执行管理**：任务看板、燃尽图、工时记录、附件评论
- **测试/质量管理**：Bug 缺陷管理、测试用例库、用例转 Bug
- **后台管理**：组织结构、用户权限、系统配置

## 4. 高价值用户流程

以下用户流程覆盖禅道核心业务闭环，建议优先实现自动化：

### 流程 1：需求全生命周期

```
1. 登录系统
2. 进入产品管理 → 需求模块
3. 创建新需求（填写标题、描述、优先级）
4. 提交需求进行评审
5. 评审通过后变更需求内容
6. 关闭需求
7. 重新激活需求
8. 验证需求关联至计划/发布
```

### 流程 2：任务看板协作

```
1. 创建项目，添加团队成员
2. 在项目中创建任务，分配给成员
3. 通过看板拖拽将任务状态变更为"进行中"
4. 登记工时（消耗/剩余）
5. 上传附件或添加评论
6. 完成任务，状态变更为"完成"
7. 验证燃尽图数据更新
```

### 流程 3：Bug 缺陷管理

```
1. 在测试模块提交 Bug（标题、步骤、预期/实际结果）
2. 关联产品版本和代码版本
3. 开发人员确认 Bug
4. 开发人员解决 Bug
5. 测试人员验证并关闭 Bug
6. 如需重新激活，进行激活操作
```

### 流程 4：用例执行与转 Bug

```
1. 进入测试模块 → 用例管理
2. 按模块查找测试用例
3. 执行用例，记录结果为"失败"
4. 将失败用例一键转为 Bug
5. 验证 Bug 自动填充了用例的步骤信息
```

## 6. 风险与假设

### 6.1 已确认事实

- ✅ 禅道系统运行于 http://localhost:8080/
- ✅ 系统支持 Chromium 浏览器访问
- ✅ 需求、任务、Bug、用例为核心功能模块
- ✅ 任务看板支持拖拽更新状态
- ✅ 用例执行支持"通过/失败/阻塞"三种结果
- ✅ 失败用例可一键转为 Bug

### 6.2 假设（待确认）

| 假设项 | 说明 |
|--------|------|
| **登录方式** | 假设为表单登录（用户名+密码），未确认是否支持 SSO 或其他认证方式 |
| **数据清理** | 测试数据是否需要在每个测试用例前清理（TEARDOWN 策略） |
| **并发限制** | 未确认是否支持多标签页/多用户并发执行 |
| **验证码** | 假设登录无图形验证码，若有则需调整策略 |
| **邮件通知** | 用例转 Bug 后是否会触发邮件通知（可能影响自动化稳定性） |
| **燃尽图渲染** | 假设为前端 Canvas/SVG 渲染，需验证截图一致性 |

### 6.3 风险项

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 登录态失效 | 测试中途会话超时 | 增加自动重试机制或每个用例前重新登录 |
| 页面加载慢 | 元素定位超时 | 使用 Playwright 智能等待，结合显式 timeout |
| 弹窗/浮层遮挡 | 元素点击失败 | 增加等待弹窗消失或强制关闭逻辑 |
| 动态 ID/类名 | 元素定位不稳定 | 优先使用 text、aria-label、data-testid 等稳定属性 |
